pub fn load(dir: &Path, verify_digests: bool) -> Result<LockedApp>
Expand description

Reads the prepared application in dir, checks the directory against its lock, and returns a locked app that Spin can run from dir in place.

dir must contain no symbolic links. Each Wasm and file source in the lock must be the path the layout gives it, and each component’s assets/<component id> directory, which is what the guest sees, must hold exactly its listed files. With verify_digests, every file is also checked against its digest. This reads the directory, and blocks while it does.

These checks hold when this function runs: Spin opens the files again later, so the caller must ensure that dir does not change while the app runs (for example, a read-only mount). The digests come from the lock in dir, so they detect a corrupted or partly changed directory, not a different application: trust a prepared directory as you would the code in it. Hard links are not detected.

In the returned app, Wasm sources are file: URLs into dir, and each component’s files become one mount of assets/<component id> at /, as for apps loaded from a registry. Nothing is written to dir.
