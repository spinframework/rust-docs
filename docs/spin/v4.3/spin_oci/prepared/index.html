Prepared application directories.

A prepared directory holds everything a Spin application from a registry needs to run, laid out ahead of time so that spin up --from-prepared can run it in place, without copying its files or accessing a registry:

<dir>/
  spin.prepared.lock      the locked app, with sources relative to <dir>
  wasm/<sha256 hex>.wasm  component, dependency and trigger dependency Wasm
  assets/<component id>/  each component's files, as the guest sees them

In the lock:

  • every Wasm source is exactly wasm/<hex>.wasm, where <hex> is the SHA-256 of the file, and keeps its sha256:<hex> digest;
  • every file has an entry of its own, whose source is exactly assets/<component id>/<path> and whose digest is the SHA-256 of the file;
  • sources are relative paths with / separators, not URLs;
  • a component without files has no assets/<component id> directory;
  • the origin metadata names the artifact pinned to its digest, and prepared_layout_version is the version of this layout.

The directory contains no symbolic links.

This is layout version 1. A Spin refuses a directory whose layout version it does not read, so a change to the layout comes with a new version.
